# Анхны шинжилгээ, алхам алхмаар

[English](WALKTHROUGH.md) · [← README](../README.mn.md)

Устгаж болох машин дээр ойролцоогоор гучин минут болно. Бүх замыг нэг удаа туулна: baseline, өөрчлөлт, хоёр дахь скан, үр дүнг унших, хоёр гүйлтийг харьцуулах. Төгсгөлд нэг finding-ийг уншиж, нотлох баримт руу нь буцаж, нэг хостын хоёр гүйлтийн ялгааг харсан байна.

## Эхлэхээс өмнө

- Өөрчилж, устгаж болох Windows машин ашиглана: Windows Sandbox эсвэл дахин тохируулж болох виртуал машин. Цуглуулагч хост дээр юуг ч өөрчилдөггүй. Доорх хоёр stand-in системийг зориуд өөрчилдөг тул хайртай машин дээр хэзээ ч бүү тавь.
- PowerShell 5.1 буюу түүнээс дээш, `Tatar.ps1` байгаа хавтас, харьцуулах алхамд Python 3 хэрэгтэй (шинжилгээний хэрэгслүүд зөвхөн стандарт сан ашигладаг).
- Энд хортой юм байхгүй, скрипт ч дагалддаггүй. Хоёр жижиг, хортой биш өөрчлөлтийг гараар хийнэ.

## 1. Baseline авах

```powershell
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process -Force
.\Tatar.ps1 -Modules sysinfo,network,indicators -OutputPath E:\Evidence -CaseId LAB-1 -Examiner "Name"
```

`-Modules` нь зөвхөн нэрлэсэн модулийг ажиллуулдаг тул хэдхэн секундэд дуусна. `-Quick`-д `indicators` ордоггүй тул энд ашиглаагүй. Гүйлт нь хост ба цагаар нэрлэсэн хавтас үүсгэнэ. Доторх `summary.txt`-ийг нээ: цэвэр машин дээр finding цөөн эсвэл огт гарахгүй байх ёстой (Sandbox дээр Sandbox-ийн өөрийн administrator акаунт гарч болно). Энэ хавтсыг хадгал, энэ бол чиний BEFORE.

## 2. Хоёр stand-in тавих

PowerShell-ийг Administrator-оор нээгээд ажиллуул:

```powershell
Add-Content C:\Windows\System32\drivers\etc\hosts "203.0.113.7 login.example.test"
Copy-Item C:\Windows\System32\notepad.exe "$env:TEMP\invoice.pdf.exe"
```

Эхний мөр hosts файлд override нэмнэ. Хаяг болон нэр нь баримт, тестэд зориулан нөөцлөгдсөн тул бодит юу ч өөр рүү чиглэхгүй. Хоёр дахь мөр системийн хортой биш програмыг давхар өргөтгөлтэйгээр temp хавтас руу хуулна, энэ нь түгээмэл өнгөлөн далдлах хэлбэр. Тэд [VALIDATION.md](VALIDATION.md)-ийн W11 ба W16-тай тохирно.

## 3. Дахин скан хийх

1-р алхмын командыг яг адилхан ажиллуул. Эхнийхийн хажууд хоёр дахь хавтас гарна. Энэ бол чиний AFTER.

## 4. Үр дүнг унших

- Шинэ `summary.txt`-ийг нээ. Finding-үүд ноцтой байдлаар эрэмбэлэгдсэн, тус бүр мессеж, дэлгэрэнгүй, зөвлөмжтэй. Hosts файлын бичилт (`network` модуль) болон temp хавтас дахь файлыг (`indicators` модуль) ол.
- Finding бүр аль тайлангийн хэсгээс гарсныг нэрлэдэг. `TATAR_Report_<HOST>_<stamp>.txt`-ийг тэр хэсэгт нээж өгүүлбэрийн ард байгаа түүхий нотлох баримтыг хар.
- Гүйлтийг браузерт харахын тулд `tools/viewer.html`-ийг нээж `summary.json`-ийг ачаал. Хуудас офлайн ажиллаж, юу ч илгээдэггүй.
- Ямар нэг зүйлийг цэвэр гэж хэлэхээсээ өмнө `tatar.log`-ийг нээж юу цуглуулаагүйг унш.

Бүртгэсэн шатанд ([VALIDATION.md](VALIDATION.md), хувилбар 1.10.0, Windows Sandbox) яг ижил хоёр stand-in finding болсон. Түүнээс хойш дэлгэрэнгүй зүйлс өөрчлөгдсөн бөгөөд цуглуулагч temp хавтас дахь executable-ийг мөн тоолдог тул хоёроос илүү finding гарч болно. Чиний харсан нь чиний build-ийн үр дүн, энэ хуудаснаас ялгаатай байвал санаа зовох бус тэмдэглэх зүйл. Finding бол хянах зүйл (lead), шийдвэр биш.

## 5. Хоёр гүйлтийг харьцуулах

```powershell
python3 tools/tatar-diff.py E:\Evidence\<BEFORE-FOLDER> E:\Evidence\<AFTER-FOLDER>
```

Үр дүн дөрвөн бүлэгтэй: шинэ, шийдэгдсэн, өөрчлөгдсөн, өөрчлөгдөөгүй. Хоёр stand-in шинэ бүлэгт, бусад бараг бүгд өөрчлөгдөөгүй бүлэгт байх ёстой. Finding-үүдийг `fingerprint`-ээр тааруулдаг бөгөөд энэ нь нэг хостын гүйлтүүдийн хооронд өөрчлөгддөггүй, тиймээс process ID эсвэл мессеж доторх тоо хуучин finding-ийг шинэ мэт харуулахгүй. `--fail-on-new` нь шинэ зүйл байвал командыг 2 кодоор дуусгадаг, ингэж хуваарьт скан дохио өгч чадна ([TOOLS.md](TOOLS.md)).

## 6. Шийд, бич

Нэг finding сонгоод [PLAYBOOKS.mn.md](PLAYBOOKS.mn.md)-ийн playbook-ийг дага. Дараа нь өөрийн хариултыг түүний хажууд бичиж, дараагийн сканд дамжуулна:

```powershell
python3 tools/tatar-review.py add reviewed.json --scan E:\Evidence\<AFTER-FOLDER> --id TTR-F-001 --verdict good --note "lab stand-in" --reviewer NAME
```

`TTR-F-001`-ийн оронд өөрийн `summary.txt` дахь finding id-г ашигла. Finding-ийг тайланд хэрхэн оруулахыг [REPORTING.mn.md](REPORTING.mn.md)-ээс хар.

## 7. Цэвэрлэх

Hosts файлд нэмсэн мөрийг устгаж, temp хавтас дахь хуулсан файлыг устга, эсвэл машиныг хая. Дараагийн алхмуудыг дахин дадлагажихыг хүсвэл хоёр нотлох хавтсыг хадгал.

## Энэ юуг харуулдаггүй

Stand-in бол халдлага биш. Энд хоёр stand-in-ийг харсан нь бодит халдлагыг харна гэсэн үг биш, лабын шатны хязгаарлалтыг [VALIDATION.md](VALIDATION.md)-д жагсаасан. Энэ хуудсыг ажлын урсгалыг сурах арга гэж үз, хэмжилт гэж бүү үз.
