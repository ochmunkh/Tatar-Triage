# Finding-ээс тайлан хүртэл

[English](REPORTING.md) · [← README](../README.mn.md)

Tatar Triage таны тайланг бичдэггүй. Буцаан мөшгөж болох нотлох баримт өгдөг бөгөөд энэ хуудас юуг иш татах, finding-ийн төрөл бүр ихэвчлэн хаана хамаарах, хязгаарыг хэрхэн хэлэх талаар өгнө. Тайлангийн хэсэгт холбох нь зохиогчийн санал, стандарт биш.

## Юуг иш татах вэ

| Зүйл | Хаана байдаг | Яагаад иш татах вэ |
|---|---|---|
| Case, шинжээч, эхлэх ба дуусах цаг, цагийн бүс, ажилласан скриптийн хэш | `chain_of_custody.txt` | Хэн, хэзээ, ямар build-ээр юу цуглуулсныг харуулна |
| Цуглуулсан файл бүрийн болон manifest-ийн өөрийн хэш | `manifest_sha256.txt`, `manifest_sha256.txt.sha256` | Уншигч файлууд хөндөгдөөгүйг баталгаажуулна |
| Хэрэгслийн хувилбар | `summary.json` дахь `version` | Ямар дүрэм finding-үүдийг гаргасныг уншигчид хэлнэ |
| Finding id (`TTR-F-NNN`) | `summary.txt`, `findings.json` | Нэг гүйлт доторх finding-ийг нэрлэнэ; гүйлтүүдийн хооронд тогтвортой биш |
| `fingerprint` | `findings.json` | Finding юу болохыг нэрлэнэ; нэг хост дээр скан бүрт ижил |
| `contentHash` | `findings.json` | Ноцтой байдал, итгэлцэл эсвэл дэлгэрэнгүй өөрчлөгдөхөд өөрчлөгдөнө |
| `evidence[]` | `findings.json` | Finding гарсан тайлангийн файл ба хэсэг |
| Юу цуглуулаагүй | `tatar.log` | Цуглуулалтын хязгаарыг хэлнэ |

| Finding-ийн ангилал | Ихэвчлэн дэмждэг тайлангийн хэсэг |
|---|---|
| `process` | Ажиллаж буй програм хангамж |
| `persistence` | Persistence |
| `privesc` | Эрх ахиулах сул тал |
| `lateral`, `sessions` | Хажуугийн хөдөлгөөн ба logon |
| `rmm` | Remote-access хэрэгслүүд |
| `useractivity`, `motw` | Хэрэглэгчийн үйл ажиллагаа ба татаж авсан зүйлс |
| `obfscan`, `indicators` | Сэжигтэй файл ба скрипт |
| `network` | Сүлжээний тохиргоо |
| `users` | Акаунтууд |
| `eventlogs` | Бүртгэл ба хөндөлт |
| `ioc` | Өөрийн indicator жагсаалттай таарсан зүйлс |
| `suid`, `sshkeys`, `bashhistory`, `context` (Linux) | Linux-д хамаарах finding |

## Нэг finding-ийг хэрхэн бичих вэ

Finding-ийг хэл, нотлох баримтыг заа, өөрийн дүгнэлтийг тусад нь өг. Ингэвэл уншигч аль хэсэг нь хэрэгслээс, аль нь чинийх гэдгийг харна:

```text
Finding TTR-F-007, fingerprint 0123456789abcdef, severity Review (tool 1.12.2).
Evidence: TATAR_Report_HOST_2026-11-19_10-00-00.txt, the section named in the finding.
Observation: the hosts file maps a login address to an unexpected IP address.
Assessment (analyst): not approved by the owner; reason for escalation.
```

Fingerprint-тэй мөр нь дараагийн тайланд тухайн finding-ийг дахин тайлбарлахгүйгээр "ижил finding одоо ч байна" гэж хэлэх боломж олгоно.

## Хязгаараа хэл

- Finding бол хянах зүйл (lead), шийдвэр биш. Хостыг эвдэрсэн гэдгээ нотлоогүй бол "цуглуулагч мэдээлсэн", "би үнэлсэн" гэж бич.
- Гүйлт эрхтэй байсан эсэхийг хэл. Administrator эсвэл root-гүй гүйлт бүгдийг уншиж чадахгүй бөгөөд дүгнэлт үүнийг хэлдэг.
- `tatar.log`-оос юу цуглуулаагүй, логийн ямар сохор цэг байгааг хэл. Цэвэр үр дүн хост цэвэр гэдгийг батлахгүй.
- Цагийн тэмдэглэлийг хэл: `chain_of_custody.txt` цагийн бүсийг тэмдэглэж, хостын цагийг гаднын цагтай тулгаагүй гэж заадаг. Өөрийнхөө хэмжсэн зөрүүг бич.

## Chain of custody

`chain_of_custody.txt`-ийн зүйлсийг тайланд хуул, өөрийн бичилтүүдийг нэм (хавтсыг хэн, хэзээ, хаашаа хуулсан), хуулбар дээр ажиллахын өмнө ба дараа хийсэн manifest шалгалтаа тэмдэглэ. Эдгээр нь ISO/IEC 27037-ийн chain-of-custody бүртгэлд хүлээгддэг зүйлсийн төрөл. Хэрэгсэл тэдгээрийг бүртгэнэ, таны процессыг стандартад нийцүүлдэггүй ([SECURITY-TESTING.md](SECURITY-TESTING.md)). Дууссан тайлан нь нотлох хавтастай адил нууц (хар [README](../README.mn.md)-гийн нотлох хавтасны нууцлалын тухай догол мөр).
